# Opportunity Scanner V2\n\n## What changed\n\nV2 turns the existing scanner into a **multi-symbol opportunity selector**.\n\nInput remains analysis-only:\n\n`GOLDBOT_OPPORTUNITY_CANDIDATES_JSON`\n\nShape:\n\n```json\n{\n  "candidates": [\n    {\n      "symbol": "BTCUSDT",\n      "direction": "long",\n      "risk_ratio_pct": 22,\n      "entry": 100,\n      "stop": 98,\n      "target": 106,\n      "gravity_4h": "long",\n      "gravity_1h": "long",\n      "leader_15m": "long",\n      "timing_5m": "long",\n      "timing_3m": "long",\n      "kfoo_tf_pct": 75,\n      "kfoo_ind_pct": 80,\n      "liquidity": {"net_ratio_pct": 18},\n      "continuity": {"side_ok": true},\n      "timestamp": "2026-09-15T06:10:00Z"\n    }\n  ]\n}\n```\n\n## Selection policy\n\n1. Reject Risk Ratio >= 60%; >= 80% is explicitly extreme.\n2. Require Reward/Risk >= 2R.\n3. Require 4H + 1H directional alignment.\n4. Require 15M leader alignment.\n5. Use 5M + 3M timing as supporting confirmation.\n6. Prefer KFOO TF >= 62.5% and indicators >= 75%.\n7. Prefer positive liquidity and continuity-average agreement.\n8. If a timestamp is supplied and is older than 120 seconds, reject the candidate.\n9. Select only a candidate scoring >= 75.\n10. If the top two tradeable candidates are within 3 score points, return NO_CLEAR_WINNER instead of forcing a choice.\n11. Repeat events with the same event_key are suppressed for Telegram during the process lifetime.\n\n## Telegram\n\nkfoo_linked_work/opportunity_scanner_v2_runner.py sends a Telegram message **only** for SELECTED.\n\nRequired environment variables:\n\n- GOLDBOT_TELEGRAM_BOT_TOKEN\n- GOLDBOT_TELEGRAM_CHAT_ID\n- GOLDBOT_TELEGRAM_ALERTS=1\n\nExecution remains **OFF**. This layer never submits exchange orders.\n\n## Runtime command\n\nFrom the repository root:\n\n```text\npython -m kfoo_linked_work.opportunity_scanner_v2_runner\n```\n\nThe upstream KFOO/V56 process is still responsible for producing the per-symbol candidate snapshots. V2 does not invent missing market data.
